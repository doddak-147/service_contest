# 실기기 QA와 사용자 검토

## 최신 상태 — 2026-11-02 운영 API 전체 배포

운영 release는 `api-1.2.0-ada4794dbbd6`다. 사용자가 배포 스크립트를 실행해 임시 서비스와 운영 서비스의 PASS를 전달했다. 기존 Python 3.12.3·FastAPI 0.141.1·Pydantic 2.13.5·httpx 0.28.1을 재사용했고 의존성 업그레이드·원본 앱 삭제·환경파일 복사는 하지 않았다. 별도 release 폴더와 systemd drop-in으로 전환했다.

개발 PC의 외부 HTTPS 요청에서도 상태 확인, 금융체력, 직접 입력 Stress Test, 현금흐름 산술, 서로 다른 주제의 5문제와 `source=llm`·대체 사유 없음을 확인했다. 가상 현금흐름의 6개월 기본 잔액 11,480,000원, 생활 충격 후 6,939,998원, 누적 이자 160,002원을 대조했다. 실제 사용자 재무값은 쓰지 않았다. 종목 검색·가격 이력·결합 분석은 JSON 503 `MARKET_DATA_UNAVAILABLE`와 `Cache-Control: no-store`를 유지했다. 이 확인은 실제 주가 공개 제공이나 실데이터 PDF 사용 허가를 의미하지 않는다.

배포 도구 테스트 11개는 패키지 해시·manifest·경로 탈출/중복/링크 거부, 원본 보존, 실제 API 산술 검사, 전환 후 실패 시 복구를 검증했다. 관련 검사 도구 전체 21개와 배포 도구를 포함한 Ruff도 통과했다. Markdown 17개의 로컬 링크에 누락이 없음을 확인했다. 운영 장애를 의도적으로 일으키는 롤백 훈련은 하지 않았다. 복구 명령은 [배포 기록](../deploy/cloud/README.md)에 있다. 아래 기록은 각 날짜·버전에서 확인한 범위다.

### 운영 HTTPS 실기기 검증

`SM S906N`(Android 16)에서 USB 포트 전달 없이 운영 HTTPS 주소를 지정한 테스트를 수행했다. 현금흐름·생활 충격·A/B 비교 1개, 입력칸·정답/오답·5문제 완료 2개, 실제 AI 표시 요구 1개를 통과했다. AI 표시 요구 검사는 첫 실행에서 자체 문제 대체로 실패했으며, 외부 서버 재요청과 해당 실기기 검사 재실행에서 `source=llm` 경로를 확인했다. 실패 사유를 숨기거나 AI 성공을 항상 보장한다고 표현하지 않는다.

이후 1.2.0(`versionCode=4`) 서명 APK를 설치하고 DEBUGGABLE 플래그가 없음을 확인했다. APK 해시와 기존 서명 지문은 아래 1.2.0 기록과 같으며 모바일 소스 변경·재빌드는 하지 않았다. 릴리스 홈의 서버 연결됨과 직접 요청한 가상 재무 예시의 6개월 현금흐름 결과를 확인했다. 당시 ADB reverse 목록은 비어 있었고 현재 앱 프로세스의 `flutter:E`·`AndroidRuntime:E` 로그는 0줄이었다. [운영 계산 화면](../output/qa/2026-11-02/cloud-release-cash-fictional.png)은 직접 입력한 가상 재무값이며 실제 시세·개인 재무정보를 포함하지 않는다. 공개 제출용 캡처는 계속 명시된 오프라인 체험을 사용한다.

이후 사용자가 물리적으로 USB를 분리하고 3개월·6개월 결과가 정상 출력된다고 확인했다. 이는 인터넷을 켠 온라인 계산이며 인터넷 없는 오프라인 검증과 구분한다.

### 서명 파일 암호화 백업

사용자가 `backup-signing-encrypted.ps1`을 실행하고 백업용 새 암호를 직접 입력했다. 실제 서명 설정·키 저장소 두 개의 AES 7-Zip 암호화, 파일명 암호화, 실제 복원 후 원본 일치 검사를 통과했다. 로컬 `.7z`(3,855바이트)의 SHA-256을 별도로 읽어 사용자 출력값과 일치함을 확인했고 임시 복원 폴더는 0개였다. 암호·서명 파일 내용은 출력하지 않았다.

브라우저 자동화는 현재 Chrome URL을 확인하지 못해 중단되었다. 사용자가 직접 Google Drive에 올리고 다운로드했다고 확인한 뒤, PC `Downloads`의 해당 파일을 읽어 원본과 동일한 3,855바이트·SHA-256 `2BCD0C9636E3DB964270DB63446547808A0F1F10B91BB73944014E1A445F2CF9`임을 검증했다. 다운로드본은 이미 실제 복원 검사한 원본 아카이브와 같으므로 복호화·암호 입력을 다시 요구하지 않았다. 업로드는 사용자 확인, 로컬 암호화·복원과 다운로드 일치는 도구 검증으로 구분한다. Drive의 계정·공유 설정을 도구로 직접 감사한 것은 아니다. 서명 파일·암호화 백업·서버 환경파일은 Git에 추가하지 않았다.

관련 Markdown 17개를 검토해 운영/비공개/오프라인 제공 범위, 구현 완료 기능, 배포·설치·백업·PC 교체 복구 절차를 맞췄다. 기존 API JSON과 계산식은 이번 마무리에서 변경하지 않았다. `AGENTS.md`의 저장소 원칙은 유효해 수정하지 않았다. `main` 병합과 다른 담당자의 리뷰는 이 작업 완료와 구분한다.

연결된 같은 Android 실기기에서 `integration_test/failure_recovery_test.dart`의 5개 테스트를 통과했다. API 응답은 앱에 주입한 모의 클라이언트와 명시된 QA 가상 수치를 사용했으며 실제 제공자의 한도를 소진시키거나 장애를 유발하지 않았다.

## 2026-11-01 운영 API와 release APK 확인

운영 Nginx의 공개 종목 API 차단을 적용하고 외부 HTTPS 요청으로 확인했다. 종목 검색·종목 위험·결합 분석은 `MARKET_DATA_UNAVAILABLE` JSON과 HTTP 503을 반환했고, `Cache-Control: no-store` 및 응답 본문·헤더의 요청 ID 일치를 확인했다. `/health`, 금융체력, 고정 Stress Test는 정상 동작했다. 운영 백엔드의 종목 어댑터 전체를 Twelve Data로 교체한 배포는 아니다.

서명된 release APK를 USB 연결 실기기에 설치했다. USB 포트 전달 없이 운영 HTTPS 서버 연결, 오프라인 체험 진입, 공개 종목 데이터 중단 안내와 기존 위험 수치 미표시를 확인했다. 홈과 분석 안내 문구도 실제 공개 API의 제공 범위에 맞췄다. Twelve Data Basic 사용 범위 밖의 공개 자료에는 오프라인 체험의 명시된 가상값만 쓴다.

추가 수정 후 1.0.1(`versionCode=2`)을 다시 빌드해 서명 검증과 실기기 설치를 통과했다. 테스트 실행기가 제거한 디버그 앱 자리에 설치했고, 실제 홈 화면의 운영 서버 연결됨과 공개 종목 중단 안내를 확인했다. 서명 인증서는 기존 설치본과 같은 SHA-256 `d9d2eead74b3e127fe8231ac8117567ec34d16fa68aa653ef9444a20792d4d54`다. APK SHA-256은 `3EB1EF80181A45047607C42437E1D9F6DB10DD7BC4A502504F1F64121830471D`다.

당시 통합 자동 검증은 API·검사 도구 테스트 합계 144개, Flutter 테스트 65개, Android 장애·복구 통합 테스트 5개, Flutter analyze 및 Python Ruff 통과였다. 서명 백업 도구의 테스트 3개는 가상 파일만 사용해 복사·해시 확인, 저장소 내부 목적지 거부, 존재 확인만 하는 모드를 검증했다. 당시 실제 서명 파일은 현재 PC에서 존재만 확인했고 외부 백업은 대기였다. 이후 Drive 백업 완료 기록은 문서 상단을 따른다. 실행 절차는 `DEMO_RUNBOOK.md`에 정리했다.

확장한 시장 데이터 검증도 같은 날 사용자가 개인 키로 실행해 `PASS` 5개를 전달했다. AAPL·AMZN 분할 조정 가격 기준점, 두 종목 지정 구간의 독립 원화 위험 검산, 미국·ECB 휴장일 경계를 확인했다. 다른 제공자의 전체 시계열 검증으로 확대 해석하지 않으며 상세 범위는 `MARKET_DATA_VALIDATION.md`를 따른다.

## 2026-11-02 기능 확장과 실기기 검증

월별 현금흐름·생활 충격, 가격/MDD 그래프, 화면 내 A·B 비교, 위험 이해 체험을 구현했다. API·스크립트 164개, 최종 Flutter 78개, Ruff·Flutter analyze를 통과했다. 가격 그래프가 기존 요약과 다른 수익률·변동성·환율 기준일을 사용할 경우 표시를 거절하는 검사도 포함한다. 새 API 계약은 기존 요청·응답을 바꾸지 않고 추가했으며 LLM 입력은 확장하지 않았다.

USB 디버깅 재승인 후 `SM S906N`(Android 16)에서 `feature_expansion_test.dart` 4개를 모두 통과했다. 실제 로컬 API의 현금흐름·생활 충격·A/B 차이, AAPL 원화·달러 가격 그래프, 가상 3·6·12개월 전환, 이해 체험 네 사례의 선택·근거·다시 시작을 확인했다. AAPL은 공개 데모 키로 조회한 63개 관측치이며 개인 키·실제 사용자 재무값을 사용하지 않았다. 실제 시계열 값은 공개 파일에 저장하지 않았다.

서명된 릴리스 설치본에서 운영 HTTPS 연결, 가상 그래프·A/B·월별 내역·누적 이자·이해 체험을 직접 확인했다. 가상 예시의 첫 달 소득 240만 원, 생활비 165만 원, 기존 상환 40만 원, 투자용 이자 26,667원이 표시됐다. A/B 비교를 스크롤해도 가상 표기가 유지되도록 제목·카드 문구를 보강하고 화면 테스트 5개와 정적 검사를 재통과했다. 재빌드한 APK를 덮어 설치해 표기를 확인했다. 확인한 릴리스 프로세스의 `flutter:E`·`AndroidRuntime:E` 로그는 0줄이었다. 이 검사는 전체 기기 로그나 모든 사용 경로의 무오류를 보증하지 않는다.

1.1.0(`versionCode=3`) release 빌드·`apksigner` 검증·실기기 설치를 통과했다. 인증서 SHA-256은 기존과 같은 `d9d2eead74b3e127fe8231ac8117567ec34d16fa68aa653ef9444a20792d4d54`, 최종 APK SHA-256은 `217E27C7C5D39170873AEE0A5F388312BDDDBFBA56F19DD99040A4B850988D34`다. 새 현금흐름·가격 API는 운영 서버 배포 전이며 공개 종목 API 차단을 해제하지 않았다. 로컬 QA 서버와 USB 포트 전달은 종료했다. 자세한 범위와 재실행 방법은 `FEATURE_EXPANSION.md`를 따른다.

## 운영 로그 점검

`scripts/audit-server-logs.py`는 서버에서 `/etc/service-contest.env`의 현재 비밀키와 보관 중인 서비스 journal을 읽어 일치하는 줄 수만 출력한다. 로그 원문·키·재무값은 출력하거나 파일로 복사하지 않는다. 로컬 PowerShell에서 검사 파일을 전송한 후 서버 SSH 터미널에서 실행한다.

```powershell
scp .\scripts\audit-server-logs.py root@211.233.194.16:/tmp/audit-server-logs.py
```

```bash
python3 /tmp/audit-server-logs.py
```

`secret_lines`가 0인지 확인하고, `sensitive_field_lines`에 잡힌 줄은 원문을 공유하지 않고 원인을 분류한다. 단어 일치만으로 민감한 값의 노출을 판정하지 않는다. 이 검사는 2026-09-26 이후 보관된 서비스 로그와 현재 환경파일의 키를 대상으로 하므로 삭제된 로그·교체 전 키·필드 이름 없이 기록된 재무 숫자의 부재까지 증명하지 않는다. 출력이 없거나 읽기 오류·로그 0줄이면 검증 완료로 표시하지 않는다.

## 외부 사용자 검토 절차

외부 사용자·금융 분야 검토는 사용자의 요청에 따라 이번 작업 범위에서 제외했다. 아래 절차는 향후 참고용이며 수행 완료로 표시하지 않는다.

팀원이 아닌 5명에게 설치본을 직접 조작하게 하고, 진행자는 처음에 기능을 설명하지 않는다. 실제 재무정보를 입력하거나 화면을 촬영해 공유할 필요가 없도록 오프라인 체험의 가상값만 사용한다. 한 사람당 10~15분으로 진행한다.

1. 첫 화면을 30초 보고 서비스가 무엇을 하는지 한 문장으로 말한다.
2. 오프라인 체험을 시작해 가상 재무 → 종목 → 결합 결과를 끝까지 본다.
3. 손실 그래프와 차입 비교가 무엇을 뜻하는지 자신의 말로 설명한다.
4. 결과가 투자 추천이나 미래 가격 예측으로 읽히는지 말한다.
5. 서버가 연결되지 않을 때 무엇을 할 수 있는지 찾는다.

진행자는 성공 여부, 걸린 시간, 멈춘 화면, 이해하지 못한 표현을 기록한다. 이름이나 개인 재무 수치는 기록하지 않는다. 같은 지점에서 2명 이상 막히거나 투자 권고로 오해하면 우선 수정한다. 수정 후 해당 과업만 다시 확인한다.

## 금융 분야 검토

금융 계산을 검토할 수 있는 외부인 1명에게 가상 예시만 보여주고 다음을 확인받는다.

- 손실액, 자기자본, 차입 원금, 이자 부담의 관계가 맞는가.
- 0인 분모와 100% 손실을 계산 불가 또는 전액 손실로 정확히 설명하는가.
- 과거 최대낙폭과 고정 주가·환율 충격을 구분하는가. 원화 기준 과거 최대낙폭에 환율 충격을 중복 적용하지 않는가.
- 출처, 기준일, 분할 조정, 배당 제외, ECB 참고 환율의 한계가 이해되는가.
- 투자 추천, 매수·매도 판단, 미래 수익 예측처럼 읽히는 문구가 있는가.

검토 의견은 `화면 / 관찰 내용 / 영향 / 수정 제안 / 재확인 결과` 순서로 적는다. 2026-11-02 사용자는 담당 교수님께 데이터 API와 UI 표현에 관한 대면 자문을 받고, 친구들의 QA·기능 평가에서 그래프와 가독성 개선 의견을 받았다고 확인했다. 이는 개발 자문과 초기 사용 점검이며, 이 절에서 계획한 금융 계산의 별도 전문 검토나 정량 효과 검증이 완료됐다는 뜻은 아니다. 세부 검토표와 반영 기록은 추가 정리 대상으로 둔다.
