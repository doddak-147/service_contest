# 실기기 QA와 사용자 검토

## 2026-11-01 검토용 버전 통합

`feature/foundation-release-integration`에 공개 종목 API 차단, 독립 데이터 검증, 서명된 release 빌드, QA 기록을 모았다. 통합 직후 API·검사 도구 테스트 133개, Flutter 테스트 63개, `flutter analyze`, API와 스크립트 Ruff를 통과했다. 생성 APK는 PC의 `output/apk/`에 보관하고 이후 Git 추적에서는 제외했다. 기존 커밋 이력은 다시 쓰지 않았다. 기본 브랜치 병합은 저장소 규칙에 따른 다른 담당자 리뷰 후 진행한다.

## 2026-10-31 확인 결과

기기: Samsung SM-S906N, Android 16. 검증용 로컬 서버는 실제 시세와 인증정보를 사용하지 않고 503 오류만 반환했다.

| 상황 | 확인 결과 |
| --- | --- |
| 종목 검색 API 503 | 오류 문구가 표시되고 검색 결과를 성공한 것처럼 보여주지 않았다. |
| 종목 위험 API 503 | 오류 문구와 재시도 버튼이 표시되고 이전 위험 수치가 남지 않았다. |
| 서버 종료 후 상태 새로고침 | 홈에 연결 실패와 연결 불가 문구가 표시됐다. |
| 서버 종료 후 오프라인 체험 | 가상 재무, 가상 종목, 결합 결과의 3단계가 완료됐다. 실제 시세·환율·AI 미사용 표시가 유지됐다. |
| 서명된 release APK 설치 | 설치와 실행에 성공했다. USB 포트 전달 없이 운영 HTTPS 서버 연결 및 오프라인 체험 진입을 확인했다. |

자동 검증: `flutter analyze` 이상 없음, `flutter test` 63개 통과. OpenAI 오류 로그의 키·긴 숫자 제거 및 Twelve Data 연결 오류 응답은 API 단위 테스트에서 확인했다. 실제 제공자의 장애, 요청 한도 초과, 운영 서버 로그 내용은 이번 실기기 검증에 포함되지 않았다.

## 2026-11-01 추가 장애·복구 검증

연결된 같은 Android 실기기에서 `integration_test/failure_recovery_test.dart`의 5개 테스트를 통과했다. API 응답은 앱에 주입한 모의 클라이언트와 명시된 QA 가상 수치를 사용했으며 실제 제공자의 한도를 소진시키거나 장애를 유발하지 않았다.

| 상황 | 결과 |
| --- | --- |
| 종목 HTTP 429·500 | 오류 표시, 위험 카드 미표시, 재시도 성공 후 카드 복구 |
| 응답 시간 초과 | 시간 초과 안내와 재시도, 뒤늦은 이전 오류 응답 무시 |
| AI 제공자 실패 | 서버의 기본 설명 응답과 사유 표시, 계산 결과 유지 |
| 설명 API 자체 실패 | 설명만 다시 요청해 복구, 결합 계산 재호출 없음 |

API 측에서도 Twelve Data와 LLM의 429·500·읽기 시간 초과를 `MockTransport`로 재현한 6개 테스트를 통과했다. 실패한 요청을 캐시에 남기지 않고 다음 요청이 복구되며, LLM 실패는 같은 검증 수치의 기본 설명으로 대체됐다.

모바일 요청 제한은 20초에서 40초로 수정했다. 서버 LLM 요청은 30초까지 기다린 후 기본 설명을 반환할 수 있어 기존 20초 제한으로는 이 응답을 받기 전에 모바일이 실패할 수 있었다. 가상 시간 테스트로 31초 뒤 응답 수신과 41초 지연 시 시간 초과·다음 요청 복구를 확인했다. 실기기 시간 초과 검증에는 짧은 주입 제한을 사용했다.

## 2026-11-01 운영 API와 release APK 확인

운영 Nginx의 공개 종목 API 차단을 적용하고 외부 HTTPS 요청으로 확인했다. 종목 검색·종목 위험·결합 분석은 `MARKET_DATA_UNAVAILABLE` JSON과 HTTP 503을 반환했고, `Cache-Control: no-store` 및 응답 본문·헤더의 요청 ID 일치를 확인했다. `/health`, 금융체력, 고정 Stress Test는 정상 동작했다. 운영 백엔드의 종목 어댑터 전체를 Twelve Data로 교체한 배포는 아니다.

서명된 release APK를 USB 연결 실기기에 설치했다. USB 포트 전달 없이 운영 HTTPS 서버 연결, 오프라인 체험 진입, 공개 종목 데이터 중단 안내와 기존 위험 수치 미표시를 확인했다. 홈과 분석 안내 문구도 실제 공개 API의 제공 범위에 맞췄다. Twelve Data Basic 사용 범위 밖의 공개 자료에는 오프라인 체험의 명시된 가상값만 쓴다.

## 운영 로그 점검

`scripts/audit-server-logs.py`는 서버에서 `/etc/service-contest.env`의 현재 비밀키와 보관 중인 서비스 journal을 읽어 일치하는 줄 수만 출력한다. 로그 원문·키·재무값은 출력하거나 파일로 복사하지 않는다. 로컬 PowerShell에서 검사 파일을 전송한 후 서버 SSH 터미널에서 실행한다.

```powershell
scp .\scripts\audit-server-logs.py root@211.233.194.16:/tmp/audit-server-logs.py
```

```bash
python3 /tmp/audit-server-logs.py
```

`secret_lines`가 0인지 확인하고, `sensitive_field_lines`에 잡힌 줄은 원문을 공유하지 않고 원인을 분류한다. 단어 일치만으로 민감한 값의 노출을 판정하지 않는다. 이 검사는 2026-09-26 이후 보관된 서비스 로그와 현재 환경파일의 키를 대상으로 하므로 삭제된 로그·교체 전 키·필드 이름 없이 기록된 재무 숫자의 부재까지 증명하지 않는다. 출력이 없거나 읽기 오류·로그 0줄이면 검증 완료로 표시하지 않는다.

2026-11-01 서버 SSH 터미널에서 실행한 결과를 사용자가 전달했다.

| 항목 | 결과 |
| --- | --- |
| 검사한 서비스 로그 | 6,122줄 |
| 현재 환경파일에서 비교한 비밀키 | 1개 |
| 현재 비밀키가 그대로 포함된 줄 | 0줄 |
| 지정한 민감 단어가 포함된 줄 | 1줄 |

추가로 원문을 출력하지 않는 분류를 실행한 결과, 1줄은 `GET` 요청의 접속 기록이고 응답은 HTTP 404였다. `authorization`은 요청 경로에 있었으며 쿼리에는 없었다. 이 기록을 인증 헤더나 재무 입력값 노출 사례로 분류하지 않았다. 지정한 재무 필드명은 발견되지 않았다. 로컬 코드의 요청 본문 미기록과 LLM 오류 로그 가림 처리도 함께 검토했으며, 검사 도구의 가상 키·재무 필드 탐지 및 출력 제한 테스트 4개와 Ruff를 통과했다.

## 외부 사용자 검토 절차

외부 사용자·금융 분야 검토는 사용자의 요청에 따라 이번 작업 범위에서 제외했다. 아래 절차는 향후 참고용이며 수행 완료로 표시하지 않는다.

팀원이 아닌 5명에게 설치본을 직접 조작하게 하고, 진행자는 처음에 기능을 설명하지 않는다. 실제 재무정보를 입력하거나 화면을 촬영해 공유할 필요가 없도록 오프라인 체험의 가상값만 사용한다. 한 사람당 10~15분으로 진행한다.

1. 첫 화면을 30초 보고 서비스가 무엇을 하는지 한 문장으로 말한다.
2. 오프라인 체험을 시작해 가상 재무 → 종목 → 결합 결과를 끝까지 본다.
3. 손실 그래프와 차입 비교가 무엇을 뜻하는지 자신의 말로 설명한다.
4. 결과가 투자 추천이나 미래 가격 예측으로 읽히는지 말한다.
5. 서버가 연결되지 않을 때 무엇을 할 수 있는지 찾는다.

진행자는 성공 여부, 걸린 시간, 멈춘 화면, 이해하지 못한 표현을 기록한다. 이름이나 개인 재무 수치는 기록하지 않는다. 같은 지점에서 2명 이상 막히거나 투자 권고로 오해하면 우선 수정한다. 수정 후 해당 과업만 다시 확인한다.

## 금융 분야 검토

금융 계산을 검토할 수 있는 외부인 1명에게 가상 예시만 보여주고 다음을 확인받는다.

- 손실액, 자기자본, 차입 원금, 이자 부담의 관계가 맞는가.
- 0인 분모와 100% 손실을 계산 불가 또는 전액 손실로 정확히 설명하는가.
- 과거 최대낙폭과 고정 주가·환율 충격을 구분하는가. 원화 기준 과거 최대낙폭에 환율 충격을 중복 적용하지 않는가.
- 출처, 기준일, 분할 조정, 배당 제외, ECB 참고 환율의 한계가 이해되는가.
- 투자 추천, 매수·매도 판단, 미래 수익 예측처럼 읽히는 문구가 있는가.

검토 의견은 `화면 / 관찰 내용 / 영향 / 수정 제안 / 재확인 결과` 순서로 적는다. 외부 검토는 아직 진행하지 않았으며 의견을 받기 전에는 완료로 표시하지 않는다.
