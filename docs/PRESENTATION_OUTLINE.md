# 공모전 발표 구성안

본선 발표 10분을 기준으로 한 10장 구성이다. 숫자와 화면은 발표 직전에 실제 앱·API 결과로 다시 확인한다.

## 1. 표지: 투자 전에 손실 감당력을 확인하다 (30초)

- 프로젝트 한 줄: 개인 재무상태와 종목의 과거 위험을 결합하는 금융위험 예방 앱
- 팀명과 팀원 4명 역할
- 화면: 앱 홈 화면 1장

발표 핵심: 수익을 약속하지 않고 가정된 하락이 내 생활에 미치는 충격을 계산한다.

## 2. 문제: 가격 하락과 부채 부담은 함께 온다 (60초)

- 한국은행: 2025년 부채 보유 가구 중 소비 제약 추정 11.1%
- 금융위원회: 20대 금융이해력 62.6점, 전체 성인 65.7점
- 한국은행: 차입 주식투자 확대가 변동성과 금융불균형을 키울 가능성
- 시각 자료: 수치 2개와 “가격 하락 + 이자 + 생활비” 관계도

출처와 해석 한계는 [공모전 대응 전략](CONTEST_STRATEGY.md)에 표시한다.

## 3. 기존 정보의 빈틈 (50초)

- 증권 서비스: 종목과 시장 정보 중심
- 금융상담: 개인의 소득·지출·부채 진단 중심
- 신용거래 안내: 일반적인 위험 경고 중심
- 빈틈: 개인 재무상태와 특정 종목의 과거 하락을 결합한 생활 충격 수치

비교 서비스에 없는 기능이라고 단정하지 말고, 공개 페이지에서 확인한 범위를 함께 말한다.

## 4. 해결 방법과 서비스 경계 (50초)

- 재무정보 입력 → 종목 과거 위험 확인 → 하락 시나리오 선택 → 결합 보고서 확인
- 제공: 예상 손실, 자기자본 영향, 이자 부담, 생활비·비상자금 영향, 회복 필요 상승률
- 제공하지 않음: 종목 추천, 매수·매도 판단, 투자 가능 여부 판정, 미래 가격 예측

## 5. 사용자 흐름 (60초)

1. 사용자가 최소 재무정보를 입력한다.
2. 종목을 검색하고 데이터 기준일과 과거 위험을 확인한다.
3. `-10%~-50%` 또는 과거 MDD 시나리오를 선택한다.
4. 결합 결과와 쉬운 한국어 설명을 확인한다.

화면은 입력, 과거 위험, 결합 보고서 순서로 한 장에 배치한다.

## 6. 계산 예시: 같은 하락도 충격은 다르다 (70초)

가정: 투자금 1,000만 원, 자기자본 600만 원, 차입금 400만 원, 연이율 6%, 월 고정지출 150만 원, 가격 `-20%`.

| 결과 | 결정론적 계산값 |
|---|---:|
| 예상 투자손실 | 200만 원 |
| 자기자본 대비 손실률 | 33.33% |
| 손실 후 자기자본 | 400만 원 |
| 연간·월 이자 | 24만 원·2만 원 |
| 고정지출 대비 손실 | 1.33개월 |
| 원금 회복 필요 상승률 | 25% |

예시일 뿐 실제 성과를 예측하지 않으며, 모든 숫자는 Python 계산 함수가 생성한다.

## 7. 아키텍처와 AI의 역할 (60초)

- Flutter 앱 → HTTPS → Naver Cloud FastAPI
- FastAPI → 주가 데이터 어댑터, 금융 계산 서비스, LLM 설명 어댑터
- 금융 계산: 테스트 가능한 결정론적 Python 코드
- LLM: 이름과 재무 원본이 아닌 최소 구조화 결과만 받아 쉬운 설명 생성
- LLM 실패 시 검증된 기본 설명을 제공하며 계산 결과는 바뀌지 않는다.

## 8. 구현 완성도와 배포 (60초)

- Naver Cloud VM, Nginx, Let's Encrypt, systemd로 공개 HTTPS 운영
- Android 실기기에서 클라우드 `/health`와 핵심 흐름 확인
- 서버 pytest 91개, 모바일 테스트 37개 통과
- Ruff, `flutter analyze` 통과
- 화면: [실기기 클라우드 연결](assets/app-home-cloud.png)과 테스트 결과 캡처

## 9. 검증과 협력 계획 (60초)

- 목표 사용자 5명 이상에게 3분 내 완료율과 오인 여부 측정
- 금융 지식 보유자에게 계산식과 용어 검토 요청
- 규제 자문 가능자에게 투자 자문 오인과 개인정보 처리 검토 요청
- 4명은 프론트/백엔드가 아니라 Vertical Slice 단위로 UI, API, 계산, 테스트를 함께 담당

완료하지 않은 검증은 계획으로 명확히 구분한다.

## 10. 기대효과와 확장 (40초)

- 투자 전 손실을 생활 단위로 이해하는 예방 경험 제공
- 금융교육·상담 현장에서 사용할 수 있는 정량 대화 자료
- 검증 후 확장: 기간별 누적 이자, 포트폴리오 충격, 상담기관 연계
- 마무리: 사용자가 “얼마나 벌 수 있나”보다 먼저 “어느 정도 손실을 감당할 수 있나”를 확인하도록 돕는다.

## 발표 자료 제작 원칙

- 한 슬라이드에는 한 주장과 한 핵심 시각 자료만 둔다.
- 통계에는 기관, 기준연도, 링크를 작은 글씨로 표시한다.
- 앱 화면은 실제 실기기 캡처를 사용하고 개인정보와 IP를 가린다.
- 시연 결과와 슬라이드 숫자가 다르면 최신 앱 결과를 기준으로 수정한다.
- 발표 중 투자 권유로 들릴 수 있는 표현을 사용하지 않는다.
