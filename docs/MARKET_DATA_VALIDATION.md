# 주가 데이터 검증 기준

## 목적

2026-11-02 최신 API 소스를 운영 서버에 반영했지만 실제 시세 제공은 재개하지 않았다. 운영 실행의 provider disabled와 Nginx 차단을 함께 유지한다. 아래 실제 제공자 점검과 독립 검산 기록은 비공개 로컬 검증이며 공개 API의 실제 종목 성공 응답을 의미하지 않는다.

종목 위험 계산이 외부 제공자의 비정상·중복 데이터나 기업행사로 인해 과장되지 않는지 확인한다. 이 문서는 API 계약을 변경하지 않으며 `adjusted_close` 입력과 MDD 검산 기준을 기록한다.

## 자동 검증

- 요청 기간 밖의 관측치는 계산에서 제외한다.
- Twelve Data 어댑터는 미국 상장 주식·ETF만 받고 날짜별 분할 조정 종가를 하나로 정규화해 날짜순으로 반환한다. 지수 자체는 제외한다. 네이버 어댑터의 과거 검증 기록은 회귀 자료로만 남긴다.
- 유한하지 않거나 음수인 가격은 제공자 오류로 처리한다.
- 관측치가 2개 미만이면 수익률·변동성·MDD를 추정하지 않고 `INSUFFICIENT_PRICE_DATA`를 반환한다.
- 100% 손실을 검증하기 위해 0원 가격은 계산 계층에서 허용하되, 실제 제공자 데이터에서는 별도 이상 여부를 확인한다.

## 독립 검산 사례

기준 배열 `10,000 → 12,000 → 9,000 → 8,000 → 11,000`의 결과는 다음과 같다.

- 기간 수익률: `11,000 / 10,000 - 1 = 10%`
- MDD: `(8,000 - 12,000) / 12,000 = -33.3333%`
- 고점일과 저점일: 두 번째 관측일, 네 번째 관측일
- 종료 가격이 12,000 미만이므로 해당 기간에는 전고점 미회복

액면분할 회귀 사례는 삼성전자 50:1 분할 전후인 2018-04-30~2018-05-08의 조정 기준 가격 `53,000 → 53,000 → 51,900 → 52,600`을 고정 fixture로 사용한다. 이 구간의 MDD는 약 `-2.0755%`이며 분할 자체가 `-98%` 수준의 허위 낙폭을 만들면 테스트가 실패한다.

## 실제 제공자 점검

2026-09-18 개발 환경에서 `005930` 검색과 최근 30일 시세 23개를 조회했다. 삼성전자 2018년 50:1 분할 구간과 카카오 2021년 5:1 분할 구간도 조회해 분할 전후 가격이 동일한 조정 기준으로 반환되고, 각각의 구간 MDD가 약 `-3.9623%`, `-2.4896%`로 계산되는 것을 확인했다. 이 실통신 확인은 CI에 넣지 않고 제출 전 같은 종목·구간으로 다시 점검한다.

2026-09-29에는 Naver Cloud 운영 API와 Android 실기기를 연결해 종목 검색, 1·3·5년 기간 변경, 기간 수익률·연환산 변동성·MDD·회복일 표시와 결합 Report 이동을 확인했다. 이 확인은 통신과 화면 흐름 검증이며 다른 제공자와의 수치 대조를 대신하지 않는다.

## 한계와 제출 전 확인

아래 2026-10-10까지의 네이버 금융 실통신 결과는 과거 개발 기록이며 현재 선택한 데이터 제공자의 검증 결과가 아니다. 현재 결과를 배당 포함 총수익률이나 미래 손실 확률로 해석하면 안 된다. 제출 전에는 다음을 다시 확인한다.

2026-10-10 로컬 개발 환경에서는 `AAPL` 검색과 최근 약 3개월의 미국 일별 시세 71개를 네이버에서 조회하고, ECB 일별 EUR 대비 USD·KRW 기준값을 날짜별로 맞춰 KRW 가격을 생성했다. 이는 연동 점검이며 조정종가 또는 투자자가 실제 체결하는 환율임을 증명하지 않는다. 미국 시세의 기업행사 조정 여부와 데이터 사용 조건을 별도로 확인해야 한다. ECB 기준값은 휴일·시차에 따라 주가일보다 최대 5일 앞설 수 있으며 그보다 오래된 환율만 있는 날은 제외한다. GitHub Actions의 평일 점검은 소스 가용성 감시일 뿐 환율 데이터 저장·배포 경로가 아니다.

2026-10-12 로컬 소스는 Twelve Data Basic 미국 주식 일별 시세(`adjust=splits`, 배당 제외)로 전환했다. MockTransport unit 테스트를 통과했고, 공개 `demo` 키로 `Apple` 검색과 2024-01-02~2024-01-05의 `AAPL` 일별 시세·ECB 결합(관측치 3개)을 확인했다. 개인 API 키로 현재 기간을 조회하거나 실기기를 검증한 것은 아니다. Basic의 비공개 심사 시연은 Twelve Data 측 이메일 답변에 따르며 공개 PDF에는 실제 시세와 파생 계산값을 사용하지 않는다. 외부 접근 가능한 운영 API에는 접근 제한 전까지 배포하지 않는다.

2026-10-27 로컬 소스에는 일부 주요 미국 종목의 한글 별칭 검색과 미국 거래소 현지 당일의 미확정 일봉 제외를 추가했다. 같은 관측 구간을 시장 위험 화면과 결합 Report가 조회하면 일봉이 장중에 달라져 수치가 어긋나던 문제를 막기 위한 조치다. 별칭은 전체 미국 종목의 한국어 번역 목록이 아니며 지수 자체는 검색 대상이 아니다. MockTransport와 Flutter widget 테스트를 통과했고, 개인 키를 사용한 로컬 API에서 `애플`→`AAPL`, `큐큐큐`→`QQQ`, `에스피와이`→`SPY` 검색을 확인했다. 한글 별칭 자체의 실기기 입력은 별도로 확인하지 않았다.

같은 날짜의 로컬 소스에서 미국 상장 ETF도 검색·원화 기준 과거 위험·결합 Report 대상으로 확대했다. Twelve Data 검색 응답의 `instrument_type=ETF`와 일별 시세 메타데이터의 `type=ETF`를 통해 주식과 구분한다. 공개 데모 키로 `SPY`·`QQQ` 검색 결과의 미국 시장·USD·Basic 표시와 `QQQ` 일별 시세의 ECB 참고 환율 결합을 확인했다. 이어 개인 키로 로컬 API에서 SPY·QQQ 검색, 두 ETF의 일별 시세·원화 환산·환율 기준일·과거 위험 지표 응답을 확인했다. USB 연결 Samsung Android 실기기에서도 두 ETF 검색 결과의 유형 표시와 위험 카드의 출처·기준일·관측치·지표·데이터 한계를 확인했다. 이 검증은 로컬 디버그 빌드이며 공개 운영 서버 검증이나 다른 출처와의 독립 수치 대조는 아니다. ETF 분배금은 가격 수익률에 포함하지 않으며 추종 지수 결과로 표시하지 않는다.

2026-10-31에는 `scripts/validate-market-data.py`를 로컬에서 실행했다. 공개 데모 키로 받은 AAPL의 2020년 4:1 분할 전후 조정 종가를 별도 [SEC 공시의 분할 전 종가](https://www.sec.gov/Archives/edgar/data/1053092/000095010320017274/dp135904_424b2-k1586.htm)와 [분할 후 종가](https://www.sec.gov/Archives/edgar/data/1666268/000095010320017171/dp135844_fwp-ps4872msfl.htm)에 대조했다. ECB 원자료에서 환율을 다시 계산하고 원화 가격의 기간 수익률·MDD·변동성을 별도 식으로 대조해 모두 통과했다. 스크립트는 실데이터 응답과 파생 수치를 파일에 저장하거나 출력하지 않는다. 첫 실행에서는 개인 키가 없어 두 번째 종목 AMZN을 건너뛰었다.

2026-11-01에는 개인 키를 사용해 같은 로컬 검증을 다시 실행했다. AAPL 분할 조정 종가, 독립 원화 수익률·MDD·변동성·환율 기준일 검증이 다시 통과했고, AMZN의 2022년 20:1 분할 전후 조정 종가도 [독립 가격 자료](https://www.sec.gov/comments/s7-30-22/s73022-20163328-333796.pdf), [분할 후 가격 자료](https://www.sec.gov/Archives/edgar/data/1665650/000182912622013265/jpm_424b2.htm), [Amazon의 분할 안내](https://ir.aboutamazon.com/faqs/default.aspx)와 대조해 통과했다. 확인된 출력은 `PASS` 3개이며 키와 실데이터 값은 공유하거나 저장하지 않았다. 이는 두 종목의 분할 조정 가격 및 AAPL 기간의 원화 위험 계산 검증이다. AMZN의 전체 기간 MDD를 다른 출처와 독립 대조한 결과로 확대 해석하지 않는다.

개인 키로 두 번째 종목까지 확인할 때는 저장소 루트에서 `.\scripts\validate-market-data.ps1`을 실행한다. 준비 메시지가 나온 **다음** 메모장에서 키 문자열만 클립보드에 복사하고 터미널에는 붙여넣지 않은 채 Enter를 누른다. 스크립트는 키 형식을 확인한 뒤 클립보드를 비우며, 키와 실데이터는 출력하거나 저장하지 않는다. 공개 데모 검증만 재실행하려면 `-PublicOnly`를 붙인다.

## 추가 검산과 휴장일 경계

2026-11-01 검증 스크립트를 확장했다. AMZN의 2022-06-02~2022-06-07 구간도 원래 USD 종가와 별도로 읽은 ECB 원자료로 원화 가격을 다시 만들고, 기간 수익률·MDD·표본 변동성·고점·저점·회복일·관측치·가격 및 환율 기준일을 대조한다. MDD는 앱의 누적 고점 순회와 별개로 가능한 고점·저점 쌍을 모두 비교한다. 다른 제공자의 전체 일별 시계열과 수치를 대조하는 검증은 아니며, 가격의 외부 참고 대조는 앞서 명시한 SEC 자료의 분할 전후 기준점에 한정한다.

공개 데모 키 실행에서는 다음 두 실제 구간의 검산을 통과했다. ECB는 [TARGET 휴장일을 제외한 영업일에 참고 환율을 발표한다](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html).

- 2020-04-09~2020-04-15: 4월 10일 미국 일봉 없음, 미국 거래일인 4월 13일에는 ECB 당일 환율이 없어 4월 9일 참고값을 사용함을 확인했다.
- 2020-09-03~2020-09-09: 9월 7일 미국 일봉은 없지만 ECB USD·KRW 참고값은 존재함을 확인했다.

공개 데모 키 실행은 AAPL 가격·원화 검산·휴장일 경계의 `PASS` 3개였다. 이어 같은 날 사용자가 PC PowerShell에서 개인 키를 사용해 전체 검증을 실행하고 다음 `PASS` 5개를 전달했다. 이로써 AMZN의 지정 구간 원화 위험·날짜 검산도 통과한 것으로 기록한다.

1. AAPL 분할 조정 USD 종가의 SEC 기준점 대조
2. AAPL 원화 수익률·MDD·변동성·환율 기준일 독립 산술 검산
3. 미국·ECB 휴장일 경계와 이전 환율 기준일 확인
4. AMZN 분할 조정 USD 종가의 SEC 기준점 대조
5. AMZN 원화 수익률·MDD·변동성·고점·저점·회복일·관측치·기준일 독립 산술 검산

Basic 호출 한도를 고려해 Twelve Data 요청 간 간격을 두며 약 2분 걸릴 수 있다. 키·시세·파생 수치 대신 검사 결과만 출력한다. 가상 가격으로 잘못된 MDD·환율 기준일·가격을 감지하는 검사 도구 테스트 2개도 통과했다. 이 기록은 위 구간의 검증이며 전체 종목·전체 과거 기간의 정확성을 보증하지 않는다.
