# 공모전 시연 대본

## 시연 전 점검

- `https://service-contest-2026-api.duckdns.org/health`가 `{"status":"ok"}`를 반환하는지 확인한다.
- 같은 URL로 빌드한 release APK를 실기기에 설치한다.
- 실제 데이터는 기준일과 출처를 함께 보여주며, MDD 값은 당일 응답을 그대로 사용한다.
- 네트워크 장애에 대비해 개인정보가 없는 전체 흐름 녹화본을 준비한다.

## 3분 시연 순서

### 0:00~0:20 홈과 서버 연결

“앱은 현재 Naver Cloud의 FastAPI 서버와 HTTPS로 연결되어 있습니다. 이 서비스는 투자 추천이나 미래 가격 예측이 아니라 가정된 손실의 개인 영향을 계산합니다.”

확인 화면: `서버 상태: 연결됨`, 공개 HTTPS 주소, 면책 문구.

### 0:20~0:55 개인 금융체력 입력

다음 시연값을 입력한다.

| 필드 | 값 |
|---|---:|
| 월 소득 | 3,000,000원 |
| 월 고정지출 | 1,500,000원 |
| 비상자금 | 5,000,000원 |
| 투자 예정금액 | 10,000,000원 |
| 자기자본 | 6,000,000원 |
| 차입금 | 4,000,000원 |
| 연이율 | 6% |

“금액은 천 단위 구분으로 읽기 쉽게 표시되고, 자기자본과 차입금의 합이 투자금과 다르면 서버가 오류를 반환합니다.”

### 0:55~1:25 종목 검색

삼성전자 `005930`을 선택하고 출처, 통화, 조회 기간과 기준일을 가리킨다.

“현재 가격을 예측하는 것이 아니라 과거 가격으로 기간 수익률, 연환산 변동성, 최대낙폭을 계산합니다.”

### 1:25~1:50 과거 위험 확인

MDD의 직전 고점, 최대 하락점, 회복일을 보여준다. 화면에 표시된 실제 값을 읽고 고정된 수치를 외우지 않는다.

“MDD는 조회 기간 중 고점에서 저점까지 가장 크게 하락한 비율입니다. 과거 값이며 미래 결과를 보장하지 않습니다.”

### 1:50~2:25 Stress Test와 결합 보고서

`-20%`를 선택한다. 기대 결과는 다음과 같다.

- 예상 투자손실: 2,000,000원
- 자기자본 대비 손실률: 33.33%
- 손실 후 자기자본: 4,000,000원
- 예상 연간 이자: 240,000원
- 예상 월 이자: 20,000원
- 고정지출 대비 손실: 약 1.33개월
- 원금 회복 필요 상승률: 25%

“같은 20% 하락을 종목 위험으로만 끝내지 않고 사용자의 자기자본, 생활비, 비상자금 기준으로 변환합니다. 이 계산은 모두 서버의 Python 코드가 수행합니다.”

### 2:25~2:50 쉬운 결과 설명

AI 설명을 연다.

“LLM은 이미 검증된 계산 결과의 일부만 받아 쉬운 한국어로 설명합니다. 이름이나 재무 원본 전체를 보내지 않으며 숫자를 새로 만들거나 수정하지 않습니다. 호출에 실패하면 계산값은 유지하고 검증된 기본 설명을 표시합니다.”

### 2:50~3:00 마무리

“이 앱의 목적은 투자를 대신 판단하는 것이 아니라, 투자 전에 손실이 내 생활에 미칠 영향을 구체적으로 확인하도록 돕는 것입니다.”

## 장애 대응

| 상황 | 대응 |
|---|---|
| 주가 제공자 지연 또는 실패 | 오류 상태를 설명하고 고정 하락 시나리오 화면으로 진행한다. 데이터를 임의로 만들지 않는다. |
| LLM 호출 실패 | 검증된 기본 설명이 계산 결과를 바꾸지 않음을 보여준다. |
| 클라우드 연결 실패 | `/health`, systemd, Nginx 순서로 확인한다. 현장에서는 녹화본으로 전환한다. |
| 화면과 발표 수치 불일치 | 앱의 최신 계산 결과를 기준으로 말하고 발표 자료를 수정한다. |

## 예상 질의응답

- 투자 자문과 무엇이 다른가: 종목·매매 행동을 추천하지 않고 사용자가 선택한 가정의 재무 충격만 계산한다.
- AI가 계산을 틀리면 어떻게 하나: AI는 계산에 참여하지 않으며 결정론적 Python 결과를 설명만 한다.
- 개인정보는 어떻게 보호하나: MVP는 회원가입과 서버 이력 저장이 없고 LLM에는 최소 계산 결과만 전달한다.
- Naver Cloud를 어떻게 활용했나: FastAPI를 VM에 배포하고 Nginx, HTTPS, systemd, ACG를 적용해 실기기에서 공개 API를 사용한다.
- 결과의 정확성을 어떻게 확인했나: 금융 공식 unit test, API test, 모바일 test와 실기기 검증을 수행했다. 외부 전문가 검토는 제출 전 완료할 계획이다.
