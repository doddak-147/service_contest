# Vertical Slice 개발 로드맵

## 1. 작업 원칙

팀원은 프론트엔드/백엔드 역할로 고정되지 않고 한 명이 하나의 기능을 UI부터 API, 계산 또는 외부 연동, 테스트까지 책임진다. 각 Slice는 `docs/API_CONTRACT.md`를 기준으로 독립 개발하며 다른 Slice의 실제 구현 대신 mock JSON을 사용할 수 있다.

2026-09-29 기준으로 네 개 Slice와 Naver Cloud 배포·실기기 시연은 완료했다. 남은 우선순위는 장애 상황 실기기 검증, 사용자·외부 검토, 공모전 제출 자료와 배포용 APK다.
2026-10-10 로컬 소스에 미국 종목 검색·ECB 날짜별 환율 결합·환율 충격 가정을 추가했다. 기존 Naver Cloud 운영 인스턴스와 APK에는 아직 이 변경을 반영하지 않았다.
2026-10-12 로컬 소스의 종목 제공자를 Twelve Data Basic의 미국 주식으로 전환했다. 국내 시세는 비활성화했고 운영 서버는 아직 구버전이다.
2026-10-27 로컬 소스에 한글 별칭 검색, 미국 거래소 현지 당일 일봉 제외, 미국 상장 ETF 검색·분석을 추가했다. 개인 키와 USB 연결 Android 실기기로 SPY·QQQ 검색 및 과거 위험 화면을 확인했다. 이는 로컬 디버그 빌드 검증이며 공개 운영 서버에는 반영하지 않았다. 다음 제출 마감은 11월 3일 상세기획서다.
2026-10-30 모바일 UI 그래프와 홈 일러스트를 `SM S906N`에서 확인했다. 오프라인 체험은 서버 없이, Stress Test 그래프는 로컬 API 연결에서 정상 동작했다. 운영 API는 `exchange_rate_change_rate` 필드를 거부하므로 클라우드 연결 앱의 Stress Test는 HTTP 422가 발생한다. 운영 서버 버전 일치 작업이 남아 있다.

- 작업 크기: 한 PR당 0.5~2일
- 브랜치: `feature/<slice>-<topic>`
- 병합 조건: Slice 완료 조건 충족 및 다른 담당자 1명 리뷰
- 공유 파일 변경: 사전 알림 후 작은 별도 PR 우선
- 기능 상태: `mock → calculation/API → UI 연결 → tested`

## 2. 공통 준비 — 병렬 개발 전

- [x] Flutter/Dart Android 앱과 단일 FastAPI 앱을 생성한다.
- [x] `pytest`, Ruff, `flutter test`, `flutter analyze` 실행 명령을 구성한다.
- [x] `API_CONTRACT.md`의 요청·응답 모델과 공통 오류 코드를 구현·contract test와 대조한다.
- [x] 각 Slice용 고정 mock JSON과 독립 검산표를 만든다.
- [x] 환경변수 이름만 포함한 `.env.example`과 secret 검사 기준을 만든다.
- [x] 투자 추천 금지, 면책, 데이터 기준일 공통 UI 문구를 확정한다.

완료 기준: 팀원 각자가 같은 날 Slice 브랜치를 시작할 수 있고 mock을 통해 다른 Slice 없이 화면과 API를 테스트할 수 있다.

## 3. Slice A — 개인 금융체력 분석

담당 범위: `financial-health`

- [x] 재무 입력 화면과 필드별 검증을 구현한다.
- [x] `POST /api/v1/financial-health/analyze` 요청·응답 schema를 구현한다.
- [x] 월 잉여현금, 비상자금 버팀 개월, 차입 비율, 월 이자 계산 함수를 구현한다.
- [x] 입력 불변식과 0인 분모의 사용자 오류를 표시한다.
- [x] 검산값, 경계값, 잘못된 입력 unit/API/UI 테스트를 작성한다.

완료 기준: 외부 API 없이 입력부터 금융체력 결과까지 독립 시연할 수 있다.

## 4. Slice B — 종목 과거 위험 분석

담당 범위: `market-risk`

- [x] 종목 검색·기간 선택 화면과 과거 위험 카드를 구현한다.
- [x] 종목 검색 및 `GET /api/v1/market-risk/...` schema를 구현한다.
- [x] 외부 주가 API 어댑터와 테스트용 fake 어댑터를 구현한다.
- [x] 조정주가 정규화, 기간 수익률, 변동성, MDD, 하락 구간을 구현한다.
- [x] 고정 가격 배열, 결측치, API 실패 unit/API/UI 테스트를 작성한다.
- [x] 제공자, 기준일, 관측치와 경고를 화면에 표시한다.
- [x] 미국 종목 검색과 최근 3개월의 원화 환산 위험 지표를 로컬에서 구현·검증한다.
- [x] Twelve Data의 일별 분할 조정·배당 제외 기준과 Basic의 비공개 시연 조건을 확인한다.
- [x] 실제 키로 미국 종목 검색·과거 시세·환율 기준일을 로컬에서 확인한다.
- [ ] 분할·병합 사례와 미국 종목의 위험 수치를 다른 출처로 독립 대조한다.
- [ ] 공개 운영 API 접근 제한과 공개 제출 자료의 가상 예시값을 준비한 뒤 시연 배포 여부를 결정한다.
- [x] USB 연결 실기기에서 SPY·QQQ ETF 검색·원화 기준 과거 위험·환율 기준일·데이터 한계를 확인한다.

완료 기준: 한 종목의 과거 위험을 출처와 함께 독립 시연하고 외부 API 실패를 안전하게 처리한다.

## 5. Slice C — Stress Test·회복 난이도·시나리오

담당 범위: `stress-test`

- [x] 8개 시나리오 비교 UI와 계산 근거 펼치기를 구현한다.
- [x] `POST /api/v1/stress-tests/analyze` schema를 구현한다.
- [x] `+20%`, `0%`, `-10%`, `-20%`, `-30%`, `-40%`, `-50%`, MDD 계산 함수를 구현한다.
- [x] 손익, 순투자지분, 손실 대비 비율, 회복 필요 상승률을 계산한다.
- [x] 0%·100% 손실, 자기자본/비상자금/지출 0, 음의 순지분 테스트를 작성한다.
- [x] 미국 종목의 주가·환율 변동을 독립 가정하고 Python에서 원화 충격을 계산한다.
- [ ] 실기기에서 환율 선택 변경, 원화 손실, 과거 MDD 중복 적용 방지를 재확인한다.

완료 기준: FinancialProfile mock과 MDD mock만으로 여덟 시나리오를 독립 시연할 수 있다.

담당 범위: `combined-report`

- [x] 개인 금융체력과 MDD 영향을 연결한 Report UI를 구현한다.
- [x] `POST /api/v1/combined-analyses` 조합 API와 실패 시 부분 결과를 구현한다.
- [x] LLM 최소 입력 DTO와 `POST /api/v1/explanations`를 구현한다.
- [x] 계산값만 사용해 쉬운 한국어를 생성하는 prompt와 정적 fallback을 작성한다.
- [x] 새 숫자, 투자 추천, 미래 예측을 거부하는 출력 검증을 구현한다.
- [x] 결합 결과 일치, 개인정보 최소화, LLM 실패 API/UI 테스트를 작성한다.

완료 기준: A~C mock으로 Report와 AI 설명을 독립 시연하고, LLM 없이도 같은 숫자와 정적 설명을 제공한다.
