# Vertical Slice 개발 로드맵

## 1. 작업 원칙

네 명은 프론트엔드/백엔드 역할로 나뉘지 않고 한 명이 하나의 기능을 UI부터 API, 계산 또는 외부 연동, 테스트까지 책임진다. 각 Slice는 `docs/API_CONTRACT.md`를 기준으로 독립 개발하며 다른 Slice의 실제 구현 대신 mock JSON을 사용할 수 있다.

- 작업 크기: 한 PR당 0.5~2일
- 브랜치: `feature/<slice>-<topic>`
- 병합 조건: Slice 완료 조건 충족 및 다른 담당자 1명 리뷰
- 공유 파일 변경: 사전 알림 후 작은 별도 PR 우선
- 기능 상태: `mock → calculation/API → UI 연결 → tested`

## 2. 공통 준비 — 병렬 개발 전

- [ ] Flutter/Dart Android 앱과 단일 FastAPI 앱을 생성한다.
- [ ] `pytest`, Ruff, `flutter test`, `flutter analyze` 실행 명령을 구성한다.
- [ ] `API_CONTRACT.md`의 요청·응답 모델과 공통 오류 코드를 팀이 검토한다.
- [ ] 각 Slice용 고정 mock JSON과 독립 검산표를 만든다.
- [ ] 환경변수 이름만 포함한 `.env.example`과 secret 검사 기준을 만든다.
- [ ] 투자 추천 금지, 면책, 데이터 기준일 공통 UI 문구를 확정한다.

완료 기준: 네 명이 같은 날 각 Slice 브랜치를 시작할 수 있고 mock을 통해 다른 Slice 없이 화면과 API를 테스트할 수 있다.

## 3. Slice A — 개인 금융체력 분석

담당 범위: `financial-health`

- [ ] 재무 입력 화면과 필드별 검증을 구현한다.
- [ ] `POST /api/v1/financial-health/analyze` 요청·응답 schema를 구현한다.
- [ ] 월 잉여현금, 비상자금 버팀 개월, 차입 비율, 월 이자 계산 함수를 구현한다.
- [ ] 입력 불변식과 0인 분모의 사용자 오류를 표시한다.
- [ ] 검산값, 경계값, 잘못된 입력 unit/API/UI 테스트를 작성한다.

완료 기준: 외부 API 없이 입력부터 금융체력 결과까지 독립 시연할 수 있다.

## 4. Slice B — 종목 과거 위험 분석

담당 범위: `market-risk`

- [ ] 종목 검색·기간 선택 화면과 과거 위험 카드를 구현한다.
- [ ] 종목 검색 및 `GET /api/v1/market-risk/...` schema를 구현한다.
- [ ] 외부 주가 API 어댑터와 테스트용 fake 어댑터를 구현한다.
- [ ] 조정주가 정규화, 기간 수익률, 변동성, MDD, 하락 구간을 구현한다.
- [ ] 고정 가격 배열, 결측치, API 실패 unit/API/UI 테스트를 작성한다.
- [ ] 제공자, 기준일, 관측치와 경고를 화면에 표시한다.

완료 기준: 한 종목의 과거 위험을 출처와 함께 독립 시연하고 외부 API 실패를 안전하게 처리한다.

## 5. Slice C — Stress Test·회복 난이도·시나리오

담당 범위: `stress-test`

- [ ] 8개 시나리오 비교 UI와 계산 근거 펼치기를 구현한다.
- [ ] `POST /api/v1/stress-tests/analyze` schema를 구현한다.
- [ ] `+20%`, `0%`, `-10%`, `-20%`, `-30%`, `-40%`, `-50%`, MDD 계산 함수를 구현한다.
- [ ] 손익, 순투자지분, 손실 대비 비율, 회복 필요 상승률을 계산한다.
- [ ] 0%·100% 손실, 자기자본/비상자금/지출 0, 음의 순지분 테스트를 작성한다.

완료 기준: FinancialProfile mock과 MDD mock만으로 여덟 시나리오를 독립 시연할 수 있다.

## 6. Slice D — 개인×종목 결합 Report·AI 설명

담당 범위: `combined-report`

- [ ] 개인 금융체력과 MDD 영향을 연결한 Report UI를 구현한다.
- [ ] `POST /api/v1/combined-analyses` 조합 API와 실패 시 부분 결과를 구현한다.
- [ ] LLM 최소 입력 DTO와 `POST /api/v1/explanations`를 구현한다.
- [ ] 계산값만 사용해 쉬운 한국어를 생성하는 prompt와 정적 fallback을 작성한다.
- [ ] 새 숫자, 투자 추천, 미래 예측을 거부하는 출력 검증을 구현한다.
- [ ] 결합 결과 일치, 개인정보 최소화, LLM 실패 API/UI 테스트를 작성한다.

완료 기준: A~C mock으로 Report와 AI 설명을 독립 시연하고, LLM 없이도 같은 숫자와 정적 설명을 제공한다.

## 7. 통합

- [ ] A~C 실제 응답을 D의 mock 대신 연결한다.
- [ ] 동일 MDD가 시장 위험, 결합 분석, 시나리오에서 일치하는지 contract test를 작성한다.
- [ ] 온보딩부터 Report까지 전체 사용자 흐름을 테스트한다.
- [ ] 느린 네트워크, 시세 장애, LLM 장애, 잘못된 입력을 실제 기기에서 확인한다.
- [ ] 재무값과 LLM payload가 로그에 남지 않는지 확인한다.

완료 기준: 새 사용자가 테스트 기기에서 3분 안에 전체 흐름을 완료하고 모든 계산이 검산표와 일치한다.

## 8. 공모전 배포와 사용자 검증

- [ ] Naver Cloud, KT Cloud, NHN Cloud 제공 조건을 비교해 하나를 선택한다.
- [ ] 단일 FastAPI 서비스를 선택한 클라우드에 배포하고 HTTPS·secret을 설정한다.
- [ ] 팀 외 사용자 5명 이상에게 결과 이해도와 오해 가능성을 테스트한다.
- [ ] 금융 지식 보유자에게 공식과 문구를, 필요 시 법률 전문가에게 서비스 경계를 검토받는다.
- [ ] 사회문제 근거, 서비스 비교, 플랫폼 활용, 외부 협력 증빙을 제출 자료에 반영한다.
- [ ] 모바일 시연 빌드, 장애 대비 녹화본, 발표용 검산 예시를 준비한다.

완료 기준: 실제 기기 시연, 배포 URL, 사용자 검증 결과, 출처가 포함된 제출 자료를 준비한다.
